## 余量规则

- 初始 60，上限 100，移动每秒消耗 2，转向不消耗。
- 首次奖励：白板 +8、工作站 +8、空调 +12、开门 +12；到达出口余量固定为 100。
- 最短路线约 7 m，熟练玩家完成时余量约 90 以上；余量归零冻结并失败。

## 视觉实现

- 全程序化 Three.js：`surfaces.js` 生成木地板、乳胶漆、地毯、卷帘、白板手写内容、外景立面、停车场、纸箱、碎花、格栅、显示屏等 Canvas 贴图；`props.js` 生成全部家具；`scene.js` 负责房间壳体、玻璃隔断与走廊、落地窗与室外、灯光与状态同步。
- 场景根节点命名 `test_zpf2-graybox_baseline`，房间壳体单面朝内，固定俯视机位可直接看进房间。
- 无 GLB、贴图或音频文件依赖，`vite.config.js` 不需要新增资产目录。
- 状态同步：房门绕铰链开合、空调显示屏与电源指示灯随启动亮起、显示器在读取工作站后点亮。

## 验收重点

- 第三视角一次看清北墙办公区、西侧白板、东侧窗边与南门前室。
- 第一视角出生首屏无遮挡，可辨认显示器背面、红椅、白板与空调。
- 桌椅、柜体、躺椅、纸箱均有碰撞；房门关闭时不可穿过，打开后门洞可通行。
- 三项检查顺序自由，房门在完成前保持锁定并给出反馈。
- `tests/test_zpf2-office.test.mjs` 覆盖初始状态、移动、碰撞、交互链、失败、可达性、注册与场景契约。
