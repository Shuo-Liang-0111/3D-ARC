# RF-08 办公室系列

正式版本：`rf08-office-v1-r13`。页面 RF-08 原先对应内部路由 `rf09`；扫描办公室 `rf08` 不属于本次修改。

| 页面 | 内部路由 | 目标 |
| --- | --- | --- |
| RF-08 办公室整理 | rf09 | 文件夹、托盘、遥控器归还正确位置 |
| RF-08-2 会前布置 | rf09-2 | 四席资料与饮水、两把椅子归位、确认会场 |
| RF-08-3 动态办公服务 | rf09-3 | 补纸、打印与配送，补充两瓶水，回收资料 |

三关共享同一场景构造器、建筑、家具和道具集合，仅初始状态与任务条件不同。第一人称渲染吊顶和灯具，第三人称隐藏；双视角分别应用。使用 G1 的现有速度控制和关节接口播放 F 动画，未修改模型、骨架、初始姿态数据、D435、共享控制映射或相机算法。办公室入口固定为支持的 G1 速度模式。

靠近后按 F，机器人沿碰撞允许的短路径迈步、转身、接触并取放；托盘与椅背使用双手。扶住椅背后由玩家用移动键推动，F 松手；释放不吸附到目标。物品状态在手部接触后提交，最后一次动作恢复站立后才结算。打印有六秒运行期，输出不能提前拿走或重复生成。动态请求有限且最多两个同时待处理。初始余量 100%，不增加倒计时压力。

场景使用既有 Cardinal 家具、地毯和墙面材质，补充真实窗洞、窗框百叶、隔断五金、木质吸音墙、会议屏、吊顶网格与 LED、绿植、纸张层次和瓶口结构。打印机有实体进出纸托盘、开口、按钮、散热孔和嵌入式 PBR 粗糙度纹理。一次 Cardinal 打印机请求遇到连接错误且未返回任务 ID，未重复提交；最终打印机由 `tools/rf08-office/make-printer.py` 精确建模，来源如实记录在资产清单。

## 构建与部署

授权主机和工作区见本次生产记录 `./authoring/server-production/rf08-office-v1/server-profile.json`。源码工作区为 `.`。安装、资产、构建和环境全部位于用户指定根目录。凭据不在项目或记录中。

- `node --test tests/rf08-office-series.test.mjs`
- `node --test --test-name-pattern='RF-09 is registered' tests/rf09-office.test.mjs`
- `npm run build`
- `node tools/rf08-office/build-candidate.mjs rN` 生成不可覆盖的新发布目录。脚本路径针对当前用户指定部署工作区；移植时需显式换成新任务授权位置。

Vite 的三条办公室正式路由返回固定构建 `/rf08-office-v1-r13/index.htm`，不注入开发客户端。静态生产构建 allowlist 已包含 RF-09 既有资产和新打印机。资产二进制不提交 Git，清单提供路径、来源和 SHA-256；打印机可由 Blender 脚本重建。

- r12 RF-08：六次正式取放，恢复站立后完成。
- r11 RF-08-2：代表席位资料/饮水、双手推椅及释放、未就绪确认、墙/玻璃阻挡、门洞短程通行。
