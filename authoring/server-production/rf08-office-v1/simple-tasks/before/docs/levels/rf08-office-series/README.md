# RF-08 办公室系列

正式版本：`rf08-office-v1-r14`。页面 RF-08 原先对应内部路由 `rf09`；扫描办公室 `rf08` 不属于本次修改。

| 页面 | 内部路由 | 目标 |
| --- | --- | --- |
| RF-08 办公室整理 | rf09 | 文件夹、托盘、遥控器归还正确位置 |
| RF-08-2 会前布置 | rf09-2 | 四席资料与饮水、两把椅子归位、确认会场 |
| RF-08-3 动态办公服务 | rf09-3 | 补纸、打印与配送，补充两瓶水，回收资料 |

三关共享同一场景构造器、建筑、家具和道具集合，仅初始状态与任务条件不同。第一人称渲染吊顶和灯具，第三人称隐藏；双视角分别应用。使用 G1 的现有速度控制和关节接口播放 F 动画，未修改模型、骨架、初始姿态数据、D435、共享控制映射或相机算法。办公室入口固定为支持的 G1 速度模式。

靠近后按 F，机器人沿碰撞允许的短路径迈步、转身、接触并取放；托盘与椅背使用双手。扶住椅背后由玩家用移动键推动，F 松手；释放不吸附到目标。物品状态在手部接触后提交，最后一次动作恢复站立后才结算。打印有六秒运行期，输出不能提前拿走或重复生成。动态请求有限且最多两个同时待处理。初始余量 100%，不增加倒计时压力。

场景使用既有 Cardinal 家具、地毯和墙面材质，补充真实窗洞、窗框百叶、隔断五金、木质吸音墙、会议屏、吊顶网格与 LED、绿植、纸张层次和瓶口结构。打印机有实体进出纸托盘、开口、按钮、散热孔和嵌入式 PBR 粗糙度纹理。一次 Cardinal 打印机请求遇到连接错误且未返回任务 ID，未重复提交；最终打印机由 `tools/rf08-office/make-printer.py` 精确建模，来源如实记录在资产清单。

## r14 运动与余量一致性修复

恢复与前面关卡相同的 G1 MuJoCo 速度策略入口，去除办公室三关的本地运动分支排除条件。共享速度策略、模型、相机和控制映射未改；推椅的前后/侧移/转向输入使用既有 `scaleMujocoVelocityForFrontend` 标定，防止再次使用未标定的 1.4 m/s、1.8 rad/s 本地速度。

三关继承原办公室的初始 100、上限 100、平移消耗 1.2 点/秒、F 交互 4 点；Q/E 单独转向、静止等待及被动漂移免扣。F 自动对齐的实际迈步沿用共享动画的移动扣除规则，原地操作动画不持续扣除。首次拿起本关任务物品奖励 10 点，正确归还、席位摆放、服务交付或椅子归位奖励 14 点；奖励按任务物品/目标登记，仅发一次，重复取放不能刷取。余量归零触发失败，R 重置恢复全部状态。

新增 7 项运动/余量回归测试，与既有 12 项系列测试及 1 项注册测试全部通过，生产构建通过。r14 浏览器中共享 MuJoCo 在线：普通 W 输入约 2 秒，余量 100 → 97.70524；Q 输入约 2 秒余量不变；无目标 F 交互 87.32184 → 83.32184。RF-08-2 定点代表动作 11 步通过，覆盖单手取放、双手扶椅、侧推约 0.605 m、松手、未就绪确认，以及墙/玻璃阻挡和门洞通行。接触误差均小于 0.035 m。三条正式入口返回 r14 固定构建且字节一致。本次没有扩展到完整路线或通关余量预算测试。
