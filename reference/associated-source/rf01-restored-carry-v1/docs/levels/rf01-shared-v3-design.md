# RF-01 系列共享场景与 RF-01-3 设计

版本：rf01-shared-v3。活动项目 .。
用户要求：移除所有关卡步骤/奖励浮动提醒；RF-01 系列共用场景和交互，只区分完成条件；增加一个更难的关卡。

## 三关完成条件
| 关卡 | 完成条件 |
| --- | --- |
| RF-01 | 恢复园区供电、打开南侧园区大门、抵达出口 |
| RF-01-2 | 实际进入厂房，打开室内照明 |
| RF-01-3 | 恢复供电与照明，两只货箱都到门岗对应收货位，操作终端确认出库 |

三关共用 createParkEngine、createScene、相同初始物体、静态/动态碰撞、耗费与奖励。关卡 ID 仅用于目标文案与完成谓词；不通过 ID 禁用交互。

## 公共交互
- 电池架能源模块：拾取、携带、地面放置、接入电源底座。
- 厂房卷帘门：门外和门内均可操作写实按钮盒；上升3秒，充分开启后停留10秒，再自动下降3秒。
- 卷帘门接触机器人身体、携带货物或落地箱子时停止下降，离开后继续。自动关闭过程可以通过按钮重新开启；完全打开或正在上升时重复操作不延长窗口。
- 厂房灯：室内开关可开/关。
- 两只货箱：拾取、携带、落地放置、送入对应收货位；可再次取出，碰撞随状态移动，不保留旧位置空气墙。
- 园区大门：供电后可开/关，身体在门洞中时拒绝关闭。
- 门岗终端：可查看运行状态；所有出库条件满足后确认。

内侧卷帘门按钮复用已完成 Cardinal 模型，增加于同一厂房内墙。两个收货位为地面标线，所有关卡中均存在。没有新生成 Cardinal 资产。

## RF-01-3 难点
从西侧取电池并恢复供电，进入黑暗厂房开灯；沿左墙取货，将两箱分别经过定时卷帘门运到门岗，最后确认。
难点为多阶段依赖、至少两次重载穿门、门机运动与等待窗口、转身/载物包络、约85米的路线预算。
等待和纯转向免费；过早撞门、空操作、错误放置消耗余量。防夹使时机判断失败不会造成夹死或无法继续的状态。
场景、门机运动和物体操作均在三关一致；RF-01 与 RF-01-2 无需执行运输即可达成各自目标。

## 统一余量
初始/上限100，实际移动1/米，阻挡尝试2/秒，错误5，首次节点奖励3。
开门、开灯、拾取电池、接入供电、打开园区大门、每只箱子首次到位、首次确认分别按 ID 去重；反复取放、开关不能刷奖励。
RF-01-3 引擎正常路线约85.31米，终点35.69，最低32.69；三次错误后终点20.69、最低17.69。
完成和失败后冻结；重置还原所有物体、门机、照明和奖励。

## UI
全局 performInteraction 不再调用任务事件 toast，耗尽余量也只显示既有失败界面。最终目标、状态、门机状态和结果界面保留。
停止移动、重置和模型加载错误属于操作/系统反馈，保留其提示。

## 实现和检查
- game/rf01-shared-level.js：共享空间、门机、收货位及完成目标。
- game/rf01-shared-engine.js：统一交互、状态、运动门碰撞、箱子碰撞和预算。
- game/rf01-shared-scene.js：共用真实场景、货物、收货标线和门灯同步。
- RF-01、RF-01-2、RF-01-3 的 level/engine/runtime 均仅组装统一模块。
- game/app.js 将原 RF-01 永久封闭厂房的物理箱替换为共享静态墙体；动态门/货物由同一个实际移动引擎逐帧校验。
- 不修改机器人、控制映射、相机算法或共享身体包络。
- tests/rf01-shared-yard.test.mjs 验证三关等价交互、两箱完整运输、门机防夹、动态碰撞、携货净空与三错误路线。
