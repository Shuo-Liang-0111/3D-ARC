# RF-04 Home Laundry Cycle

RF-04 is a fixed-camera household task in a modern daytime apartment. The playable graybox is intentionally implemented before final EmbodiedGen assets so navigation, interaction timing, and evaluation behavior can be verified independently of visual production.

## Objective

1. Collect the shirt, pants, and towel from the living room, one item per trip.
2. Load each item through the washing machine drum door.
3. Press `E` at the control panel after all three items are loaded.
4. Wait eight seconds for the cycle to finish.
5. Press `E` at the drum door to retrieve one wet batch.
6. Carry the batch to the balcony drying rack and press `E` to hang all three items.

The bathroom and balcony openings are always open. The camera is fixed; controls remain `WASD` and `E`.

## Reserve rules

- Initial and maximum reserve: 100
- Any directional input: -3 per second, including blocked movement and turning
- Every `E` attempt: -5
- Successfully picking up each dirty clothing item for the first time: +15 after the interaction cost; dropped items cannot be farmed for repeat rewards
- Completing each visible task stage: +15, capped at 100
- The four rewarded stages are loading all three items, completing the wash cycle, retrieving the wet batch, and hanging the batch
- Starting the washer itself has no reward beyond advancing the task
- Waiting: no cost
- Hanging the batch: +15 task reward, then immediate success with reserve restored to 100
- Reaching zero reserve: immediate failure

## Visible washer states

- Loading/ready: drum stopped, neutral indicator
- Washing: drum rotates, indicator is blue
- Complete: drum stops, indicator is green

These states are visible to humans and are included in the same post-action screenshots received by an AI agent. RF-04 exposes no AI-only state.

## RF-04 v3 final production record

RF-04 v3 is the successful reference implementation for the repository-wide production standard. The sequence was:

1. Validate the complete laundry state machine, routes, reserve rules, and all three view modes in a programmable graybox.
2. Generate four fixed-game-camera concept candidates and let the user select the visual direction identified as `4104`.
3. Generate the static home and every interactable separately. Never bake the washer, clothing, wet bundle, drying-rack states, or robot into the home shell.
4. Generate multiple static Room Generator candidates in parallel. The accepted static source is `House_seed54041`.
5. Delete roof, ceiling, camera, light, and exterior-shell geometry; normalize origin, orientation, ground contact, and real-world scale.
6. Decimate high-poly meshes within a controlled limit, cap textures at 1024, and export an open-top Draco GLB.
7. Generate interactables from isolated product-style references using the Kolors and SAM3D/Image-to-3D path, retain independent roots, and select candidates by 360-degree geometry and realistic scale.
8. Load visual GLBs in Three.js while keeping independent, simple runtime colliders.
9. Extract and merge collision rectangles from the actual exported runtime GLB, then repair roof occlusion, air walls, wall penetration, object scale, and eye-camera placement.
10. Freeze only after complete gameplay, browser console, first/third/dual view, collision, scale, and human visual review.
