# RF-15 逐物体真实化检查 · v0.4.3

## 范围与证据

基线 `realism-v0.3.2`。保持两种农产品的称重、装箱、尾板装车、出库确认流程，以及最终任务 UI。检查覆盖环境主 GLB 的所有语义物体类别、独立交互模型和重复实例布局；不把每个螺钉或每片叶子误称为单独人工验收。源/候选逐网格包围盒和材质审计在生产记录 `realism-v0.4.0` 下。

Cardinal doctor、capabilities 和 token-costs 均尝试通过服务器已安装 helper 调用。凭据已配置、runtime 可读，但服务不可达；两次 doctor 重试仍失败，没有提交任何新的生成任务。以下“适合 Cardinal”是工具适用性判断，不是生成已完成。已有 Cardinal 消防柜实际复用，其源路径、哈希和归一化方式写入资产 manifest；生成任务待服务恢复后按能力重新核验。

## 生产及复验

`tools/rf15/object-pass.py <project-root> <revision>` 通过 Blender 运行，从 `v0.3.2` 保留完整资产包再重建主场景。新版本拒绝覆盖旧目录；原材质图片先从 GLB 的嵌入缓冲提取到真实图像文件，再连接节点，防止重导出白膜。`tools/rf15/decode-meshopt.mjs` 为已有消防资产解码，不调用生成服务。

Cardinal 服务不可达期间未尝试更换账户或修改服务地址。待生成请求在 `tools/rf15/cardinal-object-requests.json`，状态均是未提交；恢复后先核实能力，再按独立资产检查通过情况提交，不能批量盲替换。消防柜复用属于已有 Cardinal 资产，不是本轮新生成。

实际检查记录、测试、正式浏览器路线和发布状态写在本节的最终验证条目；未完成项不能据候选截图标为通过。
