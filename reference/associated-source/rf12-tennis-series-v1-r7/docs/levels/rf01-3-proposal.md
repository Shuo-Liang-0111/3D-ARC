# RF-01-3 动态检修台安全停机（提案）

状态：设计稿，仅提案，未实现。

## 设计原则

玩家只看到一个最终目的：**“将自动检修台停入东侧黄色检修位并完成安全锁定。”**

HUD 不列出步骤、顺序、下一步提示或计时提醒。中间过程依靠场景本身被发现：移动设备、黄色导轨、检修位、控制盒、灯号、警戒音和机械动作共同表达可行操作。交互 UI 只显示通用的“F 互动”，不替玩家解释任务流程。

## 共享场景

继续复用 RF-01 的工业园区、厂房、卷帘门、灯具、能源模块、货箱、门岗终端和原有碰撞布局。开门、开灯、电池插槽和货箱仍可操作，但不作为 RF-01-3 的完成条件，也不把它们写成中间任务提醒。

## 动态元素

### 自动检修台

- 检修台沿厂房中部黄色导轨在西侧待机位和东侧黄色检修位之间往返。
- 运行、减速、停稳三种状态由状态机驱动，设备碰撞代理随模型同步。
- 检修台经过机器人附近时会产生真实阻挡；设备离开后通路恢复。
- 东侧检修位有明显的黄色框、定位块和机械锁槽，玩家无需文字说明即可理解目标位置。

### 控制盒与安全锁

- 西侧控制盒有实体旋钮、红色急停按钮和绿色“可锁定”指示灯；按钮和旋钮只使用图形符号与机械状态，不显示流程文字。
- 东侧检修位有实体锁杆和锁槽。检修台未完全停稳时锁杆会被机械限位挡住；停稳后锁杆可以转入锁槽。
- 检修台锁定后，黄色警示灯熄灭、机械锁落下、设备停止，完成条件成立。

### 动态安全臂

- 检修台靠近东侧时，安全臂自动抬起；设备离开或重新启动时，安全臂落下。
- 安全臂是动态碰撞体，机器人不能穿过正在下降的臂体。
- 红色闪灯和短促蜂鸣只表达“危险/正在运动”，绿色常亮表达“可以锁定”，不直接告诉玩家下一步动作。

## 玩家探索路径

1. 玩家从最终目的出发，在厂房内观察自动检修台、导轨和东侧黄色检修位。
2. 玩家靠近西侧控制盒，看到检修台运行状态和急停按钮；按 F 后发现设备会减速并停止，或旋钮会切换自动/手动状态。
3. 玩家沿黄色导轨外侧绕行到东侧，观察安全臂和检修台是否完全停稳。
4. 玩家尝试东侧锁杆：设备未停稳时机械限位拒绝动作；停稳后锁杆可以转入锁槽。
5. 锁杆完成后，设备保持停止、警示灯熄灭，最终目的完成。

这些步骤不以任务文字、箭头、编号、弹窗或 toast 告诉玩家；玩家通过“设备怎么动、哪里有黄色检修位、哪个机械结构能改变状态”自行推断。

## 难度控制

- 难度高于 RF-01-2，但不依赖不可见的 1 秒或 1.5 秒精确窗口。
- 检修台有清晰的减速和停稳阶段，锁定容许宽松的停稳区间；挑战来自观察运动、避开安全臂、选择绕行路线和理解机械联锁。
- 错误操作只扣除有限余量并让设备恢复自动运行，不用突然失败或重置玩家位置。
- 设备运行周期固定且可观察，玩家多看一轮即可形成自己的操作策略。
- 携带电池或货箱经过设备区时，动态设备、静态墙体和载荷包络共同参与碰撞。

## 反馈合同

- 仅保留最终目的文本和通用 F 互动提示。
- 不显示“先做什么、再做什么、去哪里、等待几秒”的任务文字。
- 视觉反馈：导轨运动、减速、红绿灯、黄色检修位、锁杆位置、机械限位。
- 听觉反馈：运行声、急停声、安全臂蜂鸣、锁杆落锁声。
- 第一视角和第三视角看到同一套动态状态。

## 实现前验收

1. 初始画面只显示最终目的，不显示步骤列表或中间任务提醒。
2. 不阅读说明文字时，仅通过模型、灯号、标线和声音可以推断设备的运动方向、目标检修位和锁定状态。
3. 检修台、安全臂、控制盒和锁杆均有权威状态机与同步碰撞代理。
4. 设备运行、减速、停稳、急停、重新启动和锁定状态在第一/第三视角一致。
5. 测试覆盖正常探索、提前锁定、设备移动中碰撞、安全臂下降、携带电池经过、重复锁定、重置和失败冻结。
