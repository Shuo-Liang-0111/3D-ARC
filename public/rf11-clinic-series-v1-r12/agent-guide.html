01 / QUICK START

所有 Agent 共用四步闭环

无论使用什么模型或 Harness，ARC 端的流程完全相同。

One four-step loop for every agent

The ARC-side workflow is identical regardless of model or harness.

  1. 1创建 Episode

    选择关卡、视角和 Harness，获取 Agent Token 与 gameUrl。

  2. 2打开游戏 URL

    必须在浏览器打开返回的 gameUrl，让机器人世界连接 Episode。

  3. 3观察并动作

    读取观察，让模型只选择 W/A/S/D/E/WAIT，再等待动作完成。

  4. 4更新记忆

    记录目标、地标、失败尝试和下一计划，直到 WIN 或 GAME_OVER。

先测试 Episode API

Shell
export ARC_AGENT_API_URL="https://your-arc-site.example"

curl -X POST "$ARC_AGENT_API_URL/api/v1/episodes" \
  -H 'content-type: application/json' \
  -d '{"level":"rf01","view":"dual","harness":"hybrid"}'

响应中的 agentToken 属于你的 Agent；gameUrl 中包含独立 Browser Token。两者都应视为临时凭据，不要公开分享。

02 / HARNESS

选择评测信息边界

Harness 决定 Agent 能看到什么，不改变游戏规则和动作空间。

Choose the evaluation boundary

The harness controls what the agent can see without changing game rules or the action space.

VISUAL纯视觉评测

截图 + 最少任务信息。适合测试真正的视觉理解，必须使用支持图片输入的模型。

HYBRID · DEFAULT多模态实用评测

截图 + HUD + 玩家位置 + 互动与调试信号。推荐首次接入和复杂 Agent。

STATE结构化状态评测

无截图，返回完整可序列化状态。适合纯文本模型、规划器和确定性基线。

使用 OpenCode 玩 ARC

OpenCode 负责模型和会话，ARC MCP Adapter 负责游戏工具。你可以在 OpenCode 中选择任意已配置模型。

Play ARC with OpenCode

OpenCode owns the model and session; the ARC MCP adapter provides game tools. Select any model configured in OpenCode.

REQUIRESOpenCodeNode.js 20+你的模型 API Key

1. 下载本地 Adapter

2. 配置本地环境

Shell
export ARC_AGENT_API_URL="https://your-arc-site.example"
export YOUR_MODEL_API_KEY="replace-in-your-shell-only"

把模型 Provider 配置在你自己的 OpenCode 中，并通过环境变量引用密钥。ARC 不要求 Packy，也不限制 OpenAI、Anthropic、GLM、Claude、Kimi 或其他 Provider。

Configure the model provider in your own OpenCode setup and reference its key through an environment variable. ARC does not require Packy and does not restrict OpenAI, Anthropic, GLM, Claude, Kimi, or other providers.

3. 在 opencode.json 添加 MCP

JSON
{
  "mcp": {
    "arc-game": {
      "type": "local",
      "command": [
        "node",
        "/ABSOLUTE/PATH/arc-agent-kit/arc-opencode-mcp.mjs"
      ],
      "enabled": true
    }
  }
}

启动后把 ARC_AGENT_PROMPT.md 交给 OpenCode。让它调用 start_episode，然后你需要打开工具返回的 gameUrl；之后 OpenCode 会循环 observe、act、update_memory。

06 / PROTOCOL & MEMORY

动作协议与长期记忆

一个 Episode 只允许一个未完成命令。Agent 必须等待返回观察的 commandId 与发送命令的 id 相同，再决定下一步。

Action protocol and persistent memory

An Episode permits only one unfinished command. Wait until the returned observation commandId matches the sent command id before deciding the next move.

ACTIONSW · A · S · D · E · WAIT

移动/转向、互动和等待。durationMs 范围为 50–1000。

TERMINAL STATUSWIN · GAME_OVER

出现任一终止状态后停止发送动作。

MEMORYPATCH /memory

保存 completed、inventory、landmarks、failedAttempts 和 nextPlan。

ARC 记忆属于 Episode，不属于某个大模型。更换模型、压缩上下文或重启 Agent 后，只要保留 Episode ID 和 Agent Token，就能重新读取。

07 / TROUBLESHOOTING

常见问题

Common issues

Episode 一直是 waiting_for_browser

在普通浏览器中打开创建 Episode 后返回的完整 gameUrl，并等待机器人资源加载完成。不要删除 URL 中的 episode、harness 或 browser_token 参数。

返回 409：上一个动作尚未完成

不要并行发送动作。轮询 latest observation，直到 commandId 匹配上一次命令，再发送下一条。

模型没有收到截图

确认 Harness 是 visual 或 hybrid，并确认模型端点支持 image_url 输入。state Harness 按设计不返回截图。

OpenCode 工具无法连接 ARC

必须在启动 OpenCode 之前导出 ARC_AGENT_API_URL。确认 node 可用、MCP 脚本是绝对路径，并从浏览器直接打开 ARC 网站验证网络。

如何公平比较不同 Agent？

固定关卡、视角、Harness、动作时长上限和最大步数。视觉 Agent 不应与读取完整 state 的 Agent 混在同一排行榜。
